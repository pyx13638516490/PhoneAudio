# 手机音频转发到电脑 · PhoneAudio

把 **Android 手机的声音**（音乐 / 视频 / 任何 App）实时转发到 **电脑音箱**播放。

无需数据线，无需在手机安装任何 App，双击脚本即可。

---

## ✨ 特性

| 特性 | 说明 |
|---|---|
| **无线** | 手机和电脑连同一个 WiFi 即可，不用插线 |
| **免装 App** | 利用 Android 11+ 系统自带的「无线调试」，手机端零安装 |
| **自动发现** | 通过 mDNS 自动找到手机，IP 和端口变了也不用管 |
| **自动配对** | 首次输入 6 位配对码，之后一劳永逸 |
| **可调延迟** | 音频缓冲可调，在「不卡顿」和「低延迟」之间自由取舍 |
| **自带排障记录** | 脚本注释里保留了完整的性能诊断数据 |

## 🔧 原理

```
手机音频采集 (AudioRecord/REMOTE_SUBMIX)
        ↓ Opus 编码
   adb TCP 隧道 (无线调试)
        ↓
电脑 scrcpy 解码 → SDL → 声卡输出
```

核心依赖 [scrcpy](https://github.com/Genymobile/scrcpy) 的 **音频转发**能力（scrcpy 2.0+，要求 Android 11 / SDK 30+）。

## 📋 环境要求

- **电脑**：Windows 10 / 11
- **手机**：Android 11 及以上（SDK 30+）
- **网络**：手机与电脑在同一局域网
- **依赖**：[scrcpy](https://github.com/Genymobile/scrcpy/releases) 4.x（含 `adb.exe`）

## 🚀 使用

### 首次使用（需要配对一次）

1. **开启开发者选项**
   `设置 → 关于手机 → 连续点击「版本号」7 次`

2. **打开无线调试**
   `设置 → 系统 → 开发者选项 → 无线调试 → 打开`

3. **获取配对码**
   进入「无线调试」→ 点击「**使用配对码配对设备**」→ 记下 **6 位数字**
   > ⚠️ 保持弹窗不要关闭，配对码几十秒后失效

4. **运行脚本**，按提示输入配对码

### 日常使用

**双击 `手机音频到电脑.bat`** 即可，脚本会自动：

1. mDNS 广播发现手机
2. `adb connect` 建立连接
3. 启动 `scrcpy --no-video` 转发音频

停止：在窗口按 **Ctrl+C**。

## ⚙️ 参数调优

编辑 `phone-audio.ps1` 顶部：

```powershell
$AudioBufferMs = 400
```

| 场景 | 建议值 |
|---|---|
| 还是卡顿 | `500` ~ `800` |
| 看视频需要音画同步 | `80` ~ `100` |
| 改用 USB 数据线 | `50`（scrcpy 默认，延迟最低）|

## 🔍 故障排查实录

> 以下是一次真实排查的完整记录，供遇到同类问题时参考。

### 症状

音频播放时**一顿一顿地卡顿**（不是完全断连）。

### 诊断过程

**① 排除带宽问题**

```
WLAN: 5GHz / 802.11ax / 信号 99% / 协商速率 1201Mbps
```

带宽和信号都非常好，**不是带宽不足**。

**② 测量抖动**

```powershell
ping -n 30 <手机IP>
```

结果：平均 8~18ms，但**最大尖峰 129ms**，>20ms 的包占 17%。

**③ 定位到 WiFi 重传**

```powershell
adb shell cmd wifi status
```

对比两次采样中 `retriedTxPackets` 与 `successfulTxPackets` 的**增量**：

```
新增成功: 3878   新增重传: 1887
实时重传率: 32.7%        ← 正常应 < 5%
```

**根因确认：手机侧 WiFi 重传率高达 32.7%**。`11ax / 80MHz / MCS11` 的高阶调制要求极高的信噪比，信噪比一波动就整包重发，音频流被反复打断。

### 解决

**措施 1：加大音频缓冲**

```powershell
$AudioBufferMs = 50  →  400
```

吸收抖动尖峰。效果：卡顿从「严重」变「轻微」。

**措施 2：降低 WiFi 频宽（关键）**

在路由器后台把 5G「**频段带宽**」从 `80MHz` 改为 `40MHz`：

```
协商速率: 1201Mbps → 573Mbps
重传率:   32.7%    → 17.9%
```

降低调制阶数后误码率大幅下降，**卡顿消失**。

> 音频流仅需约 128kbps，协商速率降到 573Mbps 对音质**毫无影响**。

### 排查中的坑

| 现象 | 真相 |
|---|---|
| `ping` 显示 22% 丢包 | **假象** —— Android 息屏时故意不响应 ICMP |
| `cmd wifi force-low-latency-mode` | 需要系统权限，普通 adb shell 被拒绝 |
| `settings put global wifi_scan_always_enabled 0` | 需要 `WRITE_SECURE_SETTINGS`，新版 HyperOS 已收紧 |
| 换信道后变差 | 是因为当时**频宽没保存成功**，变量其实是频宽而非信道 |

## ⚠️ 已知限制

- **手机重启后需要重新打开「无线调试」** —— Android 系统行为，无法绕过
- **无线调试端口会变化** —— 不影响使用，脚本用 mDNS 自动发现
- **iOS 不支持** —— scrcpy 仅支持 Android
- **无线链路质量决定体验** —— 若 WiFi 重传率居高不下，改用 USB 数据线可彻底解决

## 💡 进阶：USB 数据线模式

如果无线链路始终不理想，插上数据线是**最彻底的方案**：

- 延迟可降至 **30~50ms**（无线通常 100ms+）
- **零抖动**，不受 WiFi 环境影响
- 无需配对，不受手机重启影响

只需把 `$AudioBufferMs` 改为 `50`，并确保手机开启「USB 调试」即可。
